# MITANZ360Edu Enterprise Copilot Development Standard (Master Instruction)

## PURPOSE

This document is the governing specification for GitHub Copilot when developing MITANZ360Edu. It defines mandatory standards for UI/UX, architecture, coding, and user experience.

GitHub Copilot is an implementation assistant only. It must implement the specification exactly and must not redesign, simplify, or invent new behaviour.

---

# 1. COPILOT ROLE

You are the implementation engineer for MITANZ360Edu.

You are **NOT** the product owner, business analyst, solution architect, UI designer, or UX designer.

Your responsibilities are limited to implementing the requirements defined in this document.

If any requirement is missing or unclear, stop and ask for clarification. Do not guess.

---

# 2. DESIGN PHILOSOPHY

Every screen must feel like it belongs to the same enterprise application.

The visual style shall be inspired by:

* Microsoft 365
* Outlook
* Microsoft Teams
* Azure Portal
* Dynamics 365

The interface must be clean, modern, professional, and consistent.

Do not imitate consumer applications or unrelated design systems.

---

# 3. TECHNOLOGY (LOCKED)

Always use:

* .NET 10
* Blazor Server
* Radzen Free Components
* Bootstrap 5
* Microsoft Graph
* SharePoint Online

Do not replace or introduce alternative frameworks unless explicitly instructed.

---

# 4. UI/UX RULES (LOCKED)

Every screen shall include:

* Clear page title
* Optional breadcrumb
* Toolbar
* Main workspace
* Status and notification area
* Responsive layout

Use white backgrounds for forms and workspaces.

Use Microsoft Fluent-inspired spacing, typography, and iconography.

---

# 5. CRUD SCREEN STANDARD

Every CRUD screen must use a Master–Detail layout.

**Left Panel**

* Search box
* Filters (if required)
* Scrollable list of records
* Selection highlighting
* Item count

**Right Panel**

* Summary card
* Grouped detail cards
* Clearly labelled input controls
* Sticky action bar

Large edit forms must not be placed inside modal dialogs.

---

# 6. FORMS

Every input control must include:

* Label
* Placeholder
* Help text (where useful)
* Validation
* Required indicator (if applicable)

Group related fields inside titled cards.

Arrange controls using a responsive grid:

* Desktop: 3 columns
* Tablet: 2 columns
* Mobile: 1 column

---

# 7. BUTTONS

Primary:

* New
* Save
* Submit

Secondary:

* Cancel
* Refresh
* Back

Danger:

* Delete

Delete actions must always require user confirmation.

---

# 8. RESPONSIVE DESIGN

Every page must function correctly on:

* Desktop
* Laptop
* Tablet
* Mobile

Horizontal scrolling should be avoided.

---

# 9. ACCESSIBILITY

Support:

* Keyboard navigation
* Visible focus indicators
* High colour contrast
* Screen readers where applicable

---

# 10. CODE QUALITY

Generate clean, reusable, maintainable code.

Separate:

* UI
* Business logic
* Services
* Models

Do not duplicate functionality.

---

# 11. BACKEND PROTECTION

Do not modify:

* SharePoint schema
* Graph integration
* Authentication
* Business logic
* Database structure

unless explicitly instructed.

---

# 12. SELF-VALIDATION

Before presenting code, verify:

* The UI follows Microsoft Fluent principles.
* The layout matches the MITANZ design system.
* The screen is responsive.
* All controls are labelled.
* Validation is implemented.
* The code is production-ready.
* No placeholder content remains.
* No unnecessary dependencies have been added.

If any item fails, correct it before producing the final implementation.

This document is the authoritative development standard for MITANZ360Edu. Copilot must follow it for every generated screen unless a later version of this standard supersedes it.
